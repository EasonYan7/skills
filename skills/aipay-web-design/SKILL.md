# 支付宝 AI 付网页设计

把 AI 付官网的设计语言应用到用户自己的内容。保留三项辨识度最高的规则：首屏用中性色突出一个产品识别点，操作按接入、了解、咨询分级，多产品路径按「识别适合的方案 → 理解怎么用 → 比较 → 接入」组织。颜色服务于产品区分，功能示意服务于业务理解。

## 按交付物读取资料

- 做页面拆解、信息架构或交互设计时，读[页面与组件模式](references/patterns.md)。需要截图、已知边界或核对当前官网时，读[取证索引](references/source.md)。
- 做视觉规格或前端时，同时读[设计令牌](references/tokens.css)。CSS 按局部主题作用域提供，可映射到现有项目的变量系统。
- 做前端时，读[组件接入与本地预览](references/components.md)，按需使用 `assets/frontend-template/` 的组件与共享层。整个目录可用做起点，单组件可与原页面结构结合。编辑项目时用实际的数据、动作和品牌替换示例。
- 需要连续轮播、导航展开、滚动切章、纵滚驱动的横向换场或跨区品牌标记时，读[动效与滚动标记](references/motion.md)。其中包含首屏命令条、环形标识、数字舞台、产品离场和页脚显示带的挂载方法。按页面章节确定换场区间与停靠点，并在窄屏、矮屏及减少动态效果条件下验证行为。
- 需要保障卡、收尾 CTA 和技术支持入口时，读[保障与收尾](references/closing.md)。卡片数据和帮助链接使用站点自己的实际能力。

## 应用步骤

1. 从需求或现有页面明确受众、主任务及每个 CTA 的真实目的地。用一句话说清产品帮谁完成什么。再按实际信息选择模块。只有一个产品时，使用稳定的首屏标题和一段代表性工作流。存在独立选项且需要比较时，才添加产品章节和决策区。
2. 先建立浅色页面与清晰的内容层级。首屏给主操作实心深色、次操作细描边、辅助入口文字样式。给每个产品一套可重复识别的图标和局部强调色，并在首屏、产品章节与对比区保持一致。实现时用项目自己的品牌、文案、数据、插画和命令。
3. 根据内容决定是否使用深色对比区、滚动联动或复制命令条。用现有语义结构承载标题、产品信息和链接，再加动效。动效减少模式下保留静态产品信息；窄屏维持阅读与点击顺序。按站点加载实际内容再调断点。
4. 按请求交付设计规格、拆解结果或实际代码。设计规格应说明每个模块解决什么用户问题、主次动作、桌面和手机布局、交互状态。实现后检查首屏主路径、导航展开和关闭、焦点、实际窄屏溢出、比较区可达性，以及滚动或动效失效时内容是否可读。若目标是首次接入，按项目文档写明真正的完成信号，例如控制台出现首个已连接项目。按钮点击和命令复制在各自步骤验收。若启用固定入口，检查它与 CTA、横滑区和设备安全区的遮挡关系。

当用户要求重新提取官网时，重新打开首页并检查当前版本。用浏览器截图、DOM 与计算样式确认视觉和技术细节，标明实测状态和迁移时的调整。只在页面行为经过操作验证时写成已通过。
