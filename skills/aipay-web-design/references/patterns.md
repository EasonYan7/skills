# 页面与组件模式

来源与实拍图见[取证索引](source.md)。组件参数见[设计令牌](tokens.css)。本页每节先记录官网结构，再给出适用条件。

## 信息架构

首页阅读顺序为导航 → 首屏价值主张和入口 → 生态伙伴与规模实例 → 产品故事 → 快速对比 → 开发者资源 → 安全保障 → 底部接入动作与页脚。

| 用户问题 | 官网用的模块 | 迁移时如何选择 |
| --- | --- | --- |
| 这是做什么的，我现在能做什么 | 产品徽标首屏和三级 CTA | 把核心结果放进稳定文本，给主动作一个具体的目标 |
| 谁已经在用，有哪些实际效果 | 伙伴标识环和大数字 | 使用可核实的案例和数据，附指标名称、定义与时间口径 |
| 哪条路线适合我 | 多产品导览与独立章节 | 按任务、适用对象或业务模型划分，给每条路线统一的简短入口 |
| 它们有什么区别 | 对比表或手机对比卡 | 固定各方案共有的决策维度。分组优先于堆叠功能清单 |
| 怎么接入、验证和上线 | 工具箱、文档、SDK、沙箱和评测 | 保留用户完成当前任务所需的实际资源和状态 |
| 我能否放心使用 | 授权、留痕、身份、风控等说明 | 用自身产品支持的机制描述何时生效、用户有何控制权 |
| 下一步去哪 | 复现顶部主次动作的底部 CTA，之后是页脚分组 | 复用首屏目的地和标签，让长页读完即可行动 |

## 1. 吸顶胶囊导航

官网左侧是品牌与 Agent 友好入口，右侧是浅灰主导航胶囊和独立深色登录按钮。桌面产品菜单展开为深色分组面板，导航岛同步转深。产品按 AI 付、AI 收、连续订阅分组，产品项含图标、名称、短说明，部分带场景子入口。暗色区顶部反转为深底浅字，登录为浅底深字。980 px 及以下使用紧凑导航，390 px 实拍为深色纵向分组面板。

迁移时用披露按钮表示可展开项，链接负责跳转。控制 `aria-expanded` 与面板可见状态一致。键盘能打开和关闭菜单，Escape 后回到触发点。处理锚点与固定导航的偏移。按业务分类折叠，少量入口用简单菜单即可。

## 2. 中性色首屏与产品徽标

官网中心标题由固定前后文和轮换的产品词槽组成。高亮徽标包含图标、短标签、浅色底和细微立体质感，邻项淡化为上下残影。背景只铺很淡的低饱和彩光。首屏副文案在标题下，紧接实心接入、描边文档和文字销售，宽屏并排且高度一致。600 px 及以下标题变成三段纵排，390 px 处三个操作垂直排列。

迁移时让固定文案独立成立。多产品可以复用徽标词槽，同一槽位给长短标签预留空间，保持 CTA 位置稳定。用产品自身图标和配色。轮播保留可发现的当前链接与静态备选，降低动态效果时显示一项静态内容，并保留其他产品入口。单产品使用一个固定徽标或直接写出产品类别。

官网部分首屏状态还出现深色命令条，由任务名称、代码预览和复制图标构成。开发者产品存在真实、常用的接入命令时，可用同一模式。窄屏允许文本省略，点击仍需复制完整内容。实现后检查成功提示、失败回退、命令可选取和键盘可达性。

## 3. 可信证明与产品章节

官网用伙伴标识和两组大数字证明已有采用。规模模块按「指标名 → 大数字 → 口径与含义」阅读，滚动中的淡入属于呈现层。

宽屏产品故事是左内容右示意。正文以「标识与名称 → 用户结果 → 解释 → 特性、流程或客户场景 → 详情」组织。右栏为色彩与材质底板，内嵌高对比的简化产品界面，部分以步骤条演示状态，底部显示产品进度与详情入口。760 px 及以下，官网把共享桌面演示栏切换为随章节排列的手机视觉。

迁移时从业务选择内容结构。并列能力用小网格，真实有先后的流程用有序步骤，方案之间的取舍用并列卡片。演示选一段能讲明结果的任务，并在每一步显式标明当前状态。长叙事才考虑两栏滚动联动，正文和详情链接保持正常文档流。移动端保留同等的产品信息，使用随章静态图或轻量切换避免固定栏占满视口。

## 4. 快速对比

官网先给标题和一行决策提示，下一行集中陈列产品徽标。桌面在黑底上使用语义表格，行维度为适用商品、典型商户、核心用途，列方向为产品。细网格与灰阶表头统一区域，实拍中一列有中灰底高亮。760 px 及以下，同一组信息改成横向滚动的深灰卡片。每张卡重复行维度，右侧露出下一张，卡片按起点吸附。

迁移时用同一数据结构生成表与卡，保持字段、顺序和详情链接一致。桌面保留 `th` 行列头关系，手机让可滚动区获得明确名称，按需加入键盘滚动或前后控制。卡片超长时可自然长高。产品数量很少且每项内容长时，可改为纵向卡片；以目标设备上的比较效率选择。高亮状态需要文字或样式以外的可访问反馈，未高亮列也要可读。

## 5. 开发者资源、安全说明和收尾

官网对比区之后仍用黑色底呈现开发工具。图像以功能物件、简化界面来解释资源，再回到浅色保障区。保障卡采用轻边框、黑灰图标和不同卡幅，核心信息为标题与具体机制。结尾重复接入和文档入口，页脚集中产品、开发者资源和机构链接。

迁移时按实际路径列出入门、验证、上线中用户能做的事。对比区与工具区适合形成连续暗色章节，保障区回到白色底与清晰文字。只有能力间存在优先级时才让卡片跨列。支持角标或底部快捷入口须避开手机操作与对比卡片。使用用户自己的联系方式、法律信息及对外承诺。

## 迁移示例

给一个面向 API 开发者的用量监控产品做官网。主操作连接项目，次操作查 API 文档。单产品使用固定标题。正文用「发送用量事件 → 校验计量结果 → 配置告警」的真实工作流，桌面用左文右图，手机内联简图。有面向个人与团队的多个真实方案时再比较接入对象、用量和告警方式。支持材料选择 API 示例、SDK 与测试环境，规模区只有证据完备时才加入。
